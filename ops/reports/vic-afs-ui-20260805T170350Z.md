# VIC AFS UI exposure (Task 5)

Generated: 2026-08-05T17:03:50Z.

## Decision: wired into the existing GFS/jurisdiction explorer, not a new page

Documented already in Task 4's report, restated here: this family is 11
measures, 2 financial years, one department, one acquired edition - no
monthly/YTD cadence and no meaningful "vintage" concept yet (only
"current"), unlike MFS which genuinely warranted its own dedicated
timeline explorer. `src/frontend/app/explorers/gfs/page.tsx` already
provides exactly the right shape (a toggle between views, a measure/
year control, a results list, a citation panel) - added a third `"VIC
AFS"` toggle option rather than building a new page.

## Backend: a small, purpose-fit API (not an awkward reuse of existing endpoints)

`src/backend/routers/v2/vic_afs.py` - `/v2/vic-afs/measures` (11
measures + metadata) and `/v2/vic-afs/series?measure_type=...` (both
years' facts + citations for one measure). Considered and rejected
reusing existing endpoints:

- `/v2/tree` (compatibility_group-scoped): each `vic_afs_*` measure has
  its own dedicated 1:1 compatibility_group (by design, for the same
  contamination-proofing reason as MFS), so a single `/v2/tree` call can
  only ever return one measure's lone node - not the right shape for a
  "pick a measure, see both years" UI.
- `/v2/facts/search` (jurisdiction-only filtering): would return every
  other VIC fact too, not just this family's 22.

Path resolution for `config/measure-semantics/vic_afs.yaml` follows the
exact multi-candidate pattern established in `compatibility.py` and
`mfs.py` (repo checkout vs Docker `/app/config` bind-mount) - applied
proactively this time, since Task 12 of the prior milestone found this
exact class of bug the hard way (a production 500) when it wasn't
followed for a new router.

## UI capabilities present

| requirement | implementation |
|---|---|
| measure selector | dropdown populated from `/v2/vic-afs/measures`, replacing the "Financial year" text input when the VIC AFS tab is active (both years always shown together - there's no meaningful single-year filter for only 2 data points) |
| year | both financial years always shown as separate rows (2023-24, 2024-25) - the whole point of this small family |
| vintage selector | a static "Source vintage: current (single acquired 2024-25 edition)" badge - no vintage selector control yet, since there is only one vintage; will become a real selector once a second edition (e.g. 2025-26) is loaded |
| flow/stock indicator | a badge that switches live between "Flow (financial year)" and "Stock (point-in-time)" when the measure selector changes |
| period disclosure | each row explicitly states "(as at <period_end>)" |
| citation access | clicking a row populates a dedicated citation box (locator + cached copy path) - not the existing `CitationPanel` component, which expects three clickable URLs (landing/original/cached) this family's citations don't have; a smaller, honest citation display was built instead rather than force-fitting the data |

Never inserted into any additive annual tree - the existing `expenses`/
`liabilities` toggle options are untouched and still query `/v2/tree`
exactly as before.

## Verified in a real browser

Built the real static export, served it under its actual basePath, ran
a real backend against the now-VIC-AFS-loaded database, and drove the

- Clicking a row populates the citation box with the real locator and
  cached copy path.
- Regression check: the existing `Expenses` (200 rows) and
  `Liabilities` (129 rows) toggle views still work exactly as before -
  unaffected by the new third option.
- Zero console/page errors throughout.
