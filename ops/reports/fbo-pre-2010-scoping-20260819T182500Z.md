## FY2007-08/FY2008-09/FY2009-10: same generation as the already-loaded FY2010-11..FY2016-17

Directly confirmed: all 3 years use "Appendix A: Expenses by Function and Sub-function" /
"Table A1" (the exact same title as every FY2010-19 edition already loaded), a 3-numeric-
column layout (prior-year Outcome | current-year Estimate at Outcome | next-year Budget),
with Estimate at Outcome in column 2 - identical to the FY2010-11..FY2011-12/FY2007-08-
style generation already in `_EDITIONS`. **Now built and loaded live** (see the item 8.1
milestone entry in `data-remediation-progress.md` dated this pass) after finding and
fixing two real defects along the way:

1. **Footnote markers directly attached to "Defence" and "Contingency reserve"** (e.g.
   "Defence(a)", "Contingency reserve(c)") with no space before the footnote letter,
   breaking the label regex. Fixed with an optional `(?:\([a-z]\))?` suffix on both
   patterns.
2. **A stray space inserted inside a large number by the source PDF's own text
   extraction** (`"5, 926"` for `"5,926"`, found in the 2008-09 file's "Total other
   economic affairs" row) - a bare `[\d,]+` run would silently split this into two
   tokens and shift every subsequent column by one, corrupting the reported value
   without any quarantine signal (the row still matched 3 numbers, just the wrong 3).
   Caught only because the published Total expenses cross-check was off by $6,113m for
   that one year - not by any structural failure. Fixed by requiring each comma-group to
   be exactly 3 digits (`\d{1,3}(?:,\s?\d{3})*`), tolerating the stray space without
   accepting a malformed split. Re-verified this fix changes **zero** values across
   every one of the 9 previously-loaded years before applying it.

## FY2000-01 through FY2006-07: a real, materially different population

All 7 years have the target table, but under **"Appendix B: Expenses by Function and
Sub-function" / "Table B1"** (not "Appendix A"/"Table A1") - a real naming difference
that would need the anchor regex widened to match either letter (or a letter-agnostic
pattern). Within this "Appendix B" era, at least 2 distinct column layouts were found by
direct inspection of each year's real header, never assumed uniform:

The 2001-02/2003-04 column-order finding (Estimate at Outcome in **column 3**, not 2) is
the same class of trap already caught once this session for FY2017-18/FY2018-19 - a
blind column-2 read here would load the *next* year's original Budget forecast as if it
were an actual, silently. This must be individually verified per year, never inferred
from a neighbouring year's shape.

### The font-shift cipher (1999-00, 2001-02, 2002-03)

3 files render their Appendix B page text through a font pypdf cannot decode into
readable Unicode (`extract_text()` returns raw glyph IDs like `/G1A/G18`). `pdftotext`
*does* extract characters, but every character is substituted by a **consistent +29
ASCII-code shift** (confirmed against multiple independent words: `"7DEOH"` decodes to
`"Table"`, `"&RPPRQZHDOWK"` decodes to `"Commonwealth"` - both exact). A working decoder:

```python
def decode(c):
    if c in (' ', '\n'):
        return c
    return chr((ord(c) - 32 + 29) % 95 + 32)
```

This was verified sufficient to recover a fully readable table (labels and numbers both)
for 1999-00, 2001-02, and 2002-03 via `pdftotext -layout` piped through this decoder.
**Not yet built into any extractor** - this needs its own dedicated pre-processing step
(distinct from every other year's extraction, which uses pypdf's normal `extract_text()`
directly) and its own regression tests before being trusted for a real load. The shift
value (+29) was only confirmed for this specific document family/era; it must not be
assumed to apply to any other font-broken PDF found elsewhere in this project without its
own independent verification.

## FY1999-00 and FY2000-01: a 2-column layout, no prior-year comparative

Both years' table has only 2 numeric columns: next-year Budget, then current-year
Estimate at Outcome (no prior-year Outcome column at all - unlike every other
sub-generation found in this project). Estimate at Outcome is column 2 in both, but the
extractor's column-count/index logic would need a `num_columns=2` case added (currently
only 3, 4, and 5 are handled), and the cross-generation Total other purposes/Total
expenses proof pattern still applies directly (not yet run against real 1999-00/2000-01
data during this scoping pass - a build pass should do so before loading).

## FY1998-99: no such table exists at all

Directly confirmed via the full table of contents: 1998-99's FBO is a 58-page document
structured around "Cash Financial Information" (Outlays/Revenue totals, GFS aggregates in
its own Appendix 1/2) - it predates the accrual-based "expenses by function and
sub-function" reporting framework entirely. No "Appendix A", "Appendix B", "Table A1", or
"Table B1" mention exists anywhere in the document; the closest related content is a set
of Commonwealth-to-State specific-purpose-payment tables organised by function, a
different and much narrower table. This is a genuine absence, not an extraction failure -
correctly excluded, never force-matched against an unrelated table.
