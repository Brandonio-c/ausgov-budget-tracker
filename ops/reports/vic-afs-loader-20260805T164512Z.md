## A real bug caught by this pass's own dry-run, before any `--apply`

The **first** dry-run against a scratch DB returned `rows_validated_
publishable: 24`, not the expected 22 (11 measures x 2 years). Traced
immediately: `config/measure-semantics/vic_afs.yaml`'s first draft
listed `vic_afs_net_result`'s `source_label_variants` as `["Net result",
"Comprehensive result"]` - both rows are numerically identical for this
entity (confirmed: `6656/961` both times), so this would have produced
two facts under the *same* fact_key (no existing-DB collision to catch
it on a first `--apply`, since fact_key uniqueness is only checked
against what's already in the database, not within the same batch) -
correctly published, but semantically wrong (double-counting a single
concept). Fixed by moving `"Comprehensive result"` to
`excluded_label_variants`, mirroring the already-planned `Net assets` /
`Net worth` handling. Re-ran the dry-run: `rows_validated_publishable:
22`, confirmed via a direct per-measure count (`Counter` over every
prepared fact's `measure_type`) that every one of the 11 measures has
exactly 2 facts and there are zero duplicate fact_keys, **before**
touching the real database at all.
